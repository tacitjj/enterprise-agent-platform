# Support

## Questions and troubleshooting

Search existing issues first. If the question is not answered, open a GitHub issue with:

- the component and version or commit;
- the exact command or request;
- expected and actual behavior;
- minimal logs with credentials and private data removed;
- the operating system and relevant Java, Python, Node.js, or Docker versions.

The project is an early reference implementation and does not provide production support or response-time guarantees.

## Bugs and feature requests

Use the repository issue templates. Keep one independently reviewable topic per issue and explain the affected architecture boundary.

## Security

Do not report vulnerabilities in public issues. Follow the private process in [SECURITY.md](SECURITY.md).
