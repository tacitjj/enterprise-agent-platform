# 点联 V1 品牌与 Figma 设计基线

> 本文冻结当前阶段的品牌名称、三类界面域、视觉资产、画板规则和设计交付边界。EVENT 原型是企业工作平台的首要视觉与交互母版；正式产品继承其页面结构、导航、空间关系、卡片、抽屉和信息密度，但不复用工程代码、固定演示数据或本地业务事实。

## 1. 品牌与产品名称

| 项目 | 冻结值 |
|---|---|
| 正式品牌 | 点联 |
| 产品描述 | 企业数字员工平台 |
| 用户端 | 点联企业数字办公大厅 |
| 企业管理端 | 点联企业管理中心 |
| 平台管理端 | 点联平台运营中心 |
| 额度展示名 | 智点 |
| 固定展示换算 | `1 元 = 100 智点` |
| 技术前缀 | `dianlian` |
| REST 根路径 | `/api/v1`，不写入品牌名 |

产品文案统一使用“数字员工”。只有在说明底层实现时才使用 Agent、Run、RAG、Provider 等技术术语，用户端不把这些术语当作主要导航或按钮名称。

## 3. 色彩基线

颜色从 EVENT 原型已使用的点联品牌令牌提取，进入 Figma 后以语义 Token 管理，不允许页面直接散落未命名色值。

| Token | 色值 | 主要用途 |
|---|---|---|
| `color.brand.primary` | `#1768E5` | 主按钮、选中态、关键链接、品牌锚点 |
| `color.brand.strong` | `#0B54C5` | 悬停、按下、重点数据 |
| `color.brand.soft` | `#EAF3FF` | 选中背景、轻提示、进度区域 |
| `color.brand.cyan` | `#36B7D9` | 协作、连接和信息辅助色 |
| `color.text.primary` | `#12213D` | 主标题、正文重点 |
| `color.text.secondary` | `#53627A` | 次级说明、元数据 |
| `color.border.default` | `#DFE8F3` | 卡片、表格、输入框边界 |
| `color.canvas` | `#F3F7FC` | 管理端与办公室画布底色 |
| `color.surface` | `#FFFFFF` | 卡片、浮层、内容面 |
| `color.status.success` | `#16A47A` | 完成、可用、已确认 |
| `color.status.warning` | `#F59A23` | 等待、费用影响、需处理 |

错误、危险、停用、审批驳回等状态需另建语义 Token，并通过文字与图标共同表达，不能只依赖颜色。数字员工的岗位辅助色只能用于识别，不得取代统一品牌主色。

## 4. 视觉方向

### 4.1 企业工作平台

- 以 EVENT 的顶栏、左侧工作入口、组织大厅、员工名册、消息、任务、智点和右侧渐进抽屉为基础；EVENT 已覆盖的区域先继承，再在同一视觉语言中补充生产能力。
- 采用现代、明亮、克制的 2.5D 企业办公空间。
- 第一眼先看见“企业的数字员工团队”，再进入员工工作空间、协作房间、任务和成果。
- 员工工位、协作房间、任务看板、成果区都是真实入口，不做纯装饰场景。
- 形象有统一品牌基因，同时通过岗位服装、道具、工位和辅助色形成差异。
- 空间动效只表达真实状态变化；任务进度、等待审批和异常必须来自权威状态与可恢复事件。
- 快捷输入是补充入口。目标员工不明确时必须让用户选择，不能把首页改成“描述事情后自动找人”。

### 4.2 企业管理域与点联平台运营后台

- 企业管理域不是另一套登录门户。具备管理权限的企业成员从同一 EVENT 风格工作平台进入受限管理页面，并保留当前企业上下文。
- 点联平台运营后台面向点联内部人员，使用独立平台上下文；可以共享品牌 Token 和基础组件，但不能混入企业日常工作导航或合并权限。
- 管理页面使用更高信息密度；费用、权限、版本、审批、对账和异常必须优先保证可读性。
- 费用、权限、版本、审批、对账和异常必须优先保证可读性，不为追求空间感牺牲表格与表单效率。
- 平台端与企业端可以共享组件，不能共享权限假设；菜单隐藏不等于后端授权。

### 4.3 借鉴与差异边界

可借鉴马维斯的人格化入口、自然语言交互和任务执行感，但不得复制其页面布局、人物造型、文案、插图、图标、组件组合或动效。点联的结构必须突出企业、部门、员工授权、知识来源、记忆范围、审批、智点和经营治理。

EVENT 原型应继承“企业员工在统一工作平台中找数字员工做事”的整体表现，包括顶栏、左导航、组织大厅、消息、员工、任务、智点和渐进抽屉；固定房间、固定员工、演示身份切换、模拟进度、恢复演示数据和原型工程组织不得进入正式设计。EVENT 未覆盖的知识治理、记忆治理、企业费用管理和点联内部运营能力，在同一品牌体系中补充，但不能反过来用旧点联 UI 覆盖 EVENT 已有页面。

### 4.4 首批员工视觉与工作区差异

首批高保真优先呈现三位员工，不再沿用旧稿中的两个示例员工占位：

| 数字员工 | 岗位识别 | 工作区核心 | 必须出现的运行态 |
|---|---|---|---|
| 平面出图专员 | 视觉板、画布、品牌素材与尺寸标签 | 视觉简报、候选图对比、局部改图、多尺寸版本、图片成果预览 | 素材确认、生成中、待选版、派生中、部分尺寸失败、待版权/内容确认 |
| 法务合同审核专员 | 合同、条款标记、审阅批注与风险色阶 | 原文/建议对照、风险清单、版本差异、红线稿与依据 | 解析中、资料不足、待法务确认、高风险、已采纳/驳回、待重新审核 |
| 报价专员 | 清单、成本构成、价格版本与审批标识 | 需求结构、历史关联、计算明细、例外项、内外版报价成果 | 待确认需求、待询价、计算中、价格例外、待审批、已出报价 |

三位员工共享点联品牌与办公室空间语言，但不能只换头像和岗位名；输入、过程、成果、风险提示和人工确认入口都必须形成可见差异。知识检索和分层记忆作为三类员工的后台依据，通过引用与作用域展示，不再占用首批独立员工工位。

## 5. 画板与适配规则

- 桌面主画板宽度：`1440px`。
- 强制适配检查宽度：`1280px`；主导航、主操作、关键状态和金额不得被截断。
- V1 不设计独立移动 App、移动 H5 或钉钉/飞书页面。
- 约 36 个核心页面/大画板不等于 36 个路由；抽屉、弹窗、分栏工作区和状态变体可以在同一路由内组织。
- 页面布局使用统一栅格和间距 Token；详情页、表格、表单、办公室空间不得各建一套独立间距体系。
- 长中文标题、超长员工名、大额智点、多人群聊、无员工和无成果状态都必须在 1280px 下验证。

## 6. 三端共享组件基线

Figma 组件库至少包含：

- 企业工作平台及其管理域共用的应用壳、顶部栏、侧栏、企业切换器和身份区；点联平台运营后台使用独立权限上下文。
- 员工卡、工位节点、员工状态、能力标签和授权标签。
- 会话消息、明确目标选择器、`@`、回复引用和三种协作模式选择器。
- 任务卡、步骤时间线、负责人、依赖、检查点、执行中引导和 Run 历史。
- 成果卡、版本差异、审批状态、交付状态和远端回执。
- 平面候选图对比、局部改图标记、尺寸/格式变体与主版本血缘。
- 合同原文/建议对照、风险等级、条款定位、红线差异与法务确认。
- 报价需求清单、历史关联、计算明细、价格例外与内外版字段权限。
- 知识来源、文档处理状态、记忆候选、作用域和冲突提示。
- 智点余额、预占/实扣/释放/退回、价格快照、账本分录和费用下钻。
- 加载、空、失败、无权限、已撤权、智点不足、SSE 重连和快照恢复状态。

组件状态命名必须复用状态/权限矩阵，不允许设计稿自行用一个“已完成”合并任务、成果、审批和外部交付。

## 7. Figma 文件结构

建议按职责组织页面，不按日历阶段组织：

```text
00 Cover & Decisions
01 Foundations
02 Components
10 User Hall
20 Enterprise Center
30 Platform Center
40 Golden Flow
50 States & Edge Cases
90 Handoff & QA
```

每个核心画板至少标注：页面编号、目标角色、数据范围、默认状态、关键异常状态、主要 ViewModel、主操作和下一个动作。原型连线必须覆盖跨端 Golden Flow，不能只连接用户首页。

## 8. 技术命名基线

| 对象 | 名称 |
|---|---|
| 逻辑仓库名 | `dianlian-workforce` |
| Java 平台 | `dianlian-platform` |
| Python AI Runtime | `dianlian-ai-runtime` |
| Web 前端 | `dianlian-web` |
| 业务 Schema | `dianlian_business` |
| 上下文 Schema | `dianlian_context` |
| 运行时 Schema | `dianlian_deer_runtime` |

当前桌面工作区仍绑定旧的本地目录名。它只是本机路径，不再作为仓库、服务、包、Schema、页面或文档中的技术名称。物理目录重命名应在本轮文件变更确认后单独执行，并重新打开桌面工作区，避免中途让当前任务和文件链接失效。
