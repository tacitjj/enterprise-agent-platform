# 点联 V1 三端页面清单

> 文档用途：作为 Figma 低保真、高保真和研发 ViewModel 拆分的共同输入，冻结“设计什么、为谁设计、必须覆盖哪些状态”。本清单描述约 36 个核心页面/大画板，不代表必须建立 36 条独立前端路由。

## 1. 画板与范围约束

- 三类界面名称固定为“点联企业数字办公大厅”“点联企业管理中心”“点联平台运营中心”。企业数字办公大厅与企业管理中心共用登录、账号、活动租户和应用外壳；后者只是管理员可见的受限管理域。点联平台运营中心是内部运营后台。
- 页面编号 `U / E / P` 分别代表企业全员工作界面、同应用内企业管理界面、点联内部运营界面。一个编号可以落成路由、标签页、抽屉、全屏工作区或关键流程画板；是否拆路由由信息架构和权限边界决定，不得把编号误解为三套登录产品。
- 以 `1440px` 桌面画板作为主设计基准；`1280px` 下核心内容、主操作、状态和金额不得被截断。可折叠次要侧栏，但不能把关键操作仅藏入横向滚动。
- V1 不设计独立移动端；钉钉、飞书真实机器人、渠道 H5 和移动 App 不进入本轮画板。公众号只覆盖草稿箱交付。
- 用户端坚持“进入办公室、看见员工、选择员工做事”的主认知。自然语言快捷输入是补充入口，不能把首页改成“输入事情后自动找人”。
- EVENT 原型是企业工作平台的首要视觉与交互母版：继承顶栏、左侧工作入口、组织大厅、右侧渐进抽屉、消息/员工/任务/智点的信息密度与操作方式；不复用其工程代码，也不复制固定房间、固定员工、演示身份、假状态或恢复演示数据。房间、员工、任务和成果均来自真实企业数据。
- 所有页面至少设计 `加载中 / 空数据 / 请求失败 / 无权限或已撤权 / 局部刷新` 五类通用状态；表格与列表还需覆盖筛选无结果、分页和长文本溢出。
- 实时页面必须同时展示 `连接正常 / 正在重连 / 已断开 / 已通过快照恢复`，不能用动画假装任务仍在推进。
- 所有金额与余额统一显示为“智点”；固定说明 `1 元 = 100 智点`。内部账务仍使用整数最小单位，前端禁止浮点反算余额。

## 2. 共享领域对象基线

页面依赖列使用领域对象而非临时页面字段，三端不得各自定义一套同义状态。

| 领域 | V1 对象链 | 页面共同约束 |
|---|---|---|
| 数字员工 | `AgentTemplate → AgentVersion → EnterpriseAgent → CapabilityPack` | 平台模板、已发布版本和企业招聘实例分离；历史任务冻结版本 |
| 会话 | `Conversation + Member + MessageTarget + Message` | 单聊、群聊共用消息事实；群内必须显式选择、`@` 或回复员工 |
| 执行 | `Task + PlanVersion + Step + Run + Guidance + Checkpoint + Handoff` | 任务与 Run 分离；补充、退回、重试形成新 Run 或计划版本并保留历史 |
| 成果 | `ArtifactVersion + Approval + Delivery + RemoteReceipt` | 生成、审批、交付和远端成功是四种不同状态 |
| 知识 | `KnowledgeSpace + DocumentVersion + Citation` | 检索前鉴权，正文、引用和附件使用同一受众边界 |
| 记忆 | `MemoryCandidate + MemoryItem + MemoryScope + Conflict` | 个人、用户与员工、群与员工、项目作用域隔离；长期记忆先确认再生效 |
| 商业 | `PointAccount + PointLot + Reservation + LedgerEntry + UsageCall + RateSnapshot` | 余额来自不可变账本；预占、实扣、释放、退回分别表达 |
| 办公室 | `OfficeSnapshot` | 只做可重建读模型，不复制员工、任务、审批、成果等权威事实 |

### 2.1 首批优先员工的差异化页面要求

首批优先方向固定为“平面出图、法务合同审核、报价”。三者使用相同的员工、会话、任务、成果、审批、知识、记忆和计费内核，只通过 `CapabilityPack`、执行模板、规则及工具形成岗位差异，不能在平台核心写死三套专用流程。

| 优先员工 | 员工档案 `U-04` | 工作空间 `U-05` | 任务与执行 `U-08 / U-09` | 成果与审批 `U-11 / E-10` | 必备差异状态 | 差异化验收条件 |
|---|---|---|---|---|---|---|
| **平面出图员工** | 展示支持的出图类型、尺寸/比例、品牌素材要求、输入示例、可下载格式、是否提供可编辑文件、版权与文字校对边界 | 提供用途/渠道、画布尺寸、文案、品牌色/字体/Logo、参考图、禁用元素和附件槽；显示低清预览、变体数与本轮智点预估 | 轨迹至少包含需求结构化、素材检查、版式/提示方案、生成、文字与品牌检查、变体选择、高清导出；用户可中途改文案、尺寸、风格或指定保留元素 | 成果支持多方案并排、局部放大、尺寸/安全区检查、版本差异、素材/模型来源说明和下载包；定稿前必须经过人工文字、品牌与版权确认 | 素材缺失、尺寸待确认、字体/Logo 不可用、生成中、低清预览、文字疑似错误、品牌检查未通过、内容安全拦截、高清导出中、部分变体失败 | 输入规格在执行前可确认；修改只重算受影响步骤；每个成图能追溯输入素材、模型/能力版本和生成参数摘要；未经定稿不得显示“可发布” |
| **法务合同审核员工** | 展示支持的合同类型、适用法域/企业规则、审核维度、风险分级、输出样例和“辅助审核、不替代执业律师意见”声明 | 提供原合同、合同类型、我方身份、交易背景、重点关注项、对方版本及企业条款库范围；支持原文定位、问答和补充背景，不把合同全文默认写入长期记忆 | 轨迹至少包含文件解析/OCR、条款分段、适用规则确认、风险识别、依据检索、冲突复核、修改建议和报告生成；每条风险保留原文位置、依据、等级、建议及置信说明 | 成果至少包含风险清单、带定位审核报告、修改建议/修订稿和引用依据；高风险、法域不明、模板冲突及对外定稿必须由有权限的法务/审批人确认 | 文件无法解析、扫描件 OCR 中、合同类型待确认、法域待确认、条款缺失、依据不足、规则冲突、高风险待处理、建议待确认、人工法务复核中、已退回 | 风险项可逐条定位和处理；模型不得虚构法律依据；未确认信息明确标为待核实；任务完成不等于合同已获法律批准，审批结果和审核版本可追溯 |
| **报价员工** | 展示支持的报价类型、所需需求字段、可用历史案例/价格规则范围、输出格式、待询价与人工调整边界 | 支持文本/图片/文件录入需求，提供结构化需求确认、历史案例关联、项目条件、税费/币种/有效期和特殊说明区域；先确认关键需求再计算 | 轨迹至少包含需求提取、缺项确认、案例/价格资产检索、规则版本冻结、计算、待询价项标记、人工调整、复算及审批；展示每项来源、数量、单价、公式和负责人 | 成果支持报价明细、计算依据、来源/案例引用、调整痕迹、版本差异、PDF/表格导出；正式对外报价必须走金额与权限匹配的审批链 | 需求缺项、识别歧义、历史案例不足、价格版本冲突、待询价、计算中、超阈值调整、利润/预算规则告警、待审批、已退回、报价过期 | 同一输入和冻结规则版本可复算；所有人工改单留痕；模型不能直接决定最终金额、折扣和审批；报价完成、审批通过和对外交付分别表达 |

知识与记忆仍是三类员工的共用底座：平面出图可检索已授权品牌规范、素材与历史已确认成图，合同审核可检索已授权模板、条款库和企业制度，报价可检索已授权价格资产、规则及历史案例。所有召回均先鉴权并提供 `Citation`；长期偏好或经验只能先生成 `MemoryCandidate`，经用户确认后写入对应 `MemoryScope`。合同正文、个人偏好、群聊经验和项目事实不得因员工类型不同而跨作用域共享。

## 7. Figma 与研发交付检查

- 每个核心画板必须标出页面角色、数据权限和主要 ViewModel 来源，不能只交付静态视觉稿。
- 主按钮、次按钮、危险操作、无权限操作及其下一步都必须定义；不可用按钮必须解释原因。
- 关键弹窗/抽屉至少覆盖提交前确认、执行中、成功、失败、重复提交和状态已变化六类结果。
- 任务、审批、交付、计费的状态名称必须复用共享状态字典；页面不得自行创造“完成”来合并不同业务结果。
- 用户端人物、工位和状态动效必须由真实数据驱动；装饰性动作不表达业务进度。
- 管理端金额、版本和高权限操作必须展示生效范围、操作者、时间、审批状态和审计入口。
- 1440 主画板完成后逐页在 1280 宽度复核导航、表格、详情侧栏、金额列和主操作；验收截图同时保留两种宽度。
- 约 36 个核心大画板之外，状态变体、弹窗、抽屉和空/错/权限态作为组件或分支画板管理，不以增加路由数量作为完成度指标。
