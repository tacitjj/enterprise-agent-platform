# ADR-039：保留 React 19 并逐步演进为生产前端

- 状态：已接受
- 日期：2026-08-11
- 决策范围：`dianlian-web`

## 背景

当前 `dianlian-web` 已使用 React 19、React Router 和 Vite 实现点联三端高保真原型，并沉淀了办公室、群聊、任务、成果、企业端和平台端交互。重新建立一套 Vue 工程会形成两套页面、状态映射和验收资产，增加重写成本，并延迟真实接口接入。

原型代码可以作为交互和视觉实现起点，但原型通过不等于已经达到生产级权限、类型、接口、错误、缓存和测试要求。

## 决策

1. 当前保留 React 19，不另起 Vue 重写。
2. `dianlian-web` 逐步从 JavaScript/JSX 迁移到 TypeScript/TSX，不进行一次性全量改写。
3. 新增的 API 客户端、公共领域类型、权限/状态映射、SSE 客户端和高风险业务模块优先使用 TypeScript。
4. 现有 JSX 页面按真实接口接入顺序迁移；未进入当前 Golden Slice 的页面不为追求迁移比例提前重构。
5. 页面只消费 OpenAPI/事件契约和服务端 `allowedActions`，不得继续把 Mock Store 作为权限、任务、成果或智点真相。
6. 办公室、企业端和平台端可以共享设计系统、API 基础设施与领域类型，但路由壳、权限边界和数据可见范围保持分离。
7. 原型 Mock 数据保留为 Story/演示或测试 Fixture 时必须与生产数据入口隔离，生产构建不得以 Mock 回退掩盖接口失败。

## 渐进迁移顺序

1. 先建立 TypeScript 配置、OpenAPI 类型生成边界、统一 ProblemDetail 和 SSE 客户端。
2. 迁移 Session、OfficeSnapshot、TaskSnapshot 和统一事件信封等公共类型。
3. 按 Golden Slice 迁移办公室、任务详情和群聊触发链。
4. 再按真实业务阶段迁移企业端和平台端页面。

## 影响

- 现有视觉和交互资产可以继续使用，避免维护 React 原型与 Vue 生产端两套实现。
- React 原型中的权威事实复制、页面本地状态推断和 Mock 行为必须在对应模块接入真实接口时移除。
- React、Vite 或 Router 的主版本升级需要单独验证三端路由、构建、SSE、错误边界和浏览器兼容性。

## 验收门槛

- 新增契约类型不使用 `any` 绕过状态和错误枚举。
- SSE 重连、事件去重、reset 恢复和撤权清理有定向测试。
- Mock 与真实 API 入口可在构建期明确区分，生产构建不包含静默 Mock 回退。
- 1280px 与 1440px 关键页面保持现有视觉验收基线。
